Phase 1: The Concept

How do robots think?

The Avoidance Logic 🧠

To make a robot avoid obstacles, we run a continuous loop of Sense → Think → Act.

  1. Sense: Use the ultrasonic sensor to check if the path ahead is clear.
  2. Think: Is there an obstacle within 20 cm?
    • No: Keep going forward.
    • Yes: Stop! Look left and right to find the best alternative path.
  3. Act: Turn towards the direction with more space, then resume driving.

The Flow Chart

Our loop() runs this every cycle:

1. SENSE → read forward distance with measureDistance()

2. THINK → is distance < 20 cm?

  • Path clear → keep driving forward, servo stays centred at 90°
  • Obstacle! → stop, scan left (180°), scan right (0°), pick the larger gap

3. ACT → turn ~300 ms toward the larger gap, then loop back to SENSE

Like a security guard scanning the room before deciding where to walk.

Phase 3: Complete Setup

Pins, libraries, Serial.

The Full Setup Block 🔧

Session 4 brings together motors, ultrasonic, and servo. Here is the complete top of your sketch:

#include <Servo.h>

// Motors (from Session 2)
#define ML_Ctrl 4
#define ML_PWM  5
#define MR_Ctrl 2
#define MR_PWM  6

// Ultrasonic (from Session 3)
const int trigPin = 12;
const int echoPin = 13;

// Servo (from Session 3) — plugged into pin 10
Servo myServo;

void setup() {
  pinMode(ML_Ctrl, OUTPUT); pinMode(ML_PWM, OUTPUT);
  pinMode(MR_Ctrl, OUTPUT); pinMode(MR_PWM, OUTPUT);

  pinMode(trigPin, OUTPUT);
  pinMode(echoPin, INPUT);

  myServo.attach(10);
  myServo.write(90); // Look forward

  Serial.begin(9600);
}

The measureDistance() Helper 📡

You wrote this in Session 3 — drop it into your sketch unchanged:

int measureDistance() {
  digitalWrite(trigPin, LOW);
  delayMicroseconds(2);
  digitalWrite(trigPin, HIGH);
  delayMicroseconds(10);
  digitalWrite(trigPin, LOW);

  long duration = pulseIn(echoPin, HIGH);
  return duration * 0.034 / 2;
}

Phase 4: Decision Making

Teaching the robot to choose a path.

The lookAt() Helper 👀

When an obstacle is detected, the robot needs to look in different directions. Instead of repeating “write angle, delay, measure” every time, we package it into one helper:

int lookAt(int angle) {
  myServo.write(angle);
  delay(500);              // Give the servo time to turn
  return measureDistance();
}

Now “look left and report the distance” is just one line:

int leftDistance  = lookAt(180); // Look left

Tip

Every time you write the same 3+ lines twice, ask: should this be a helper? Helper functions keep loop() short and readable.

Phase 5: The Main Loop

Putting it all together.

The Brain 🧠

This is the heart of the autonomous explorer:

void loop() {
  // 1. SENSE — servo is already at 90° from last iteration
  int distance = measureDistance();
  Serial.print("Forward: "); Serial.println(distance);

  if (distance > 0 && distance < 20) {
    // 2. THINK — obstacle! stop and scan
    car_Stop();
    delay(100);

    int distLeft  = lookAt(180);
    int distRight = lookAt(0);

    myServo.write(90); // Re-centre BEFORE turning
    delay(200);

    // 3. ACT — turn toward the larger gap
    if (distLeft > distRight) {
      car_left();
    } else {
      car_right();
    }
    delay(300);
  } else {
    // Path clear — keep going
    car_front();
  }
}

Important

We re-centre the servo to 90° after scanning. Without this, the next forward measurement reads sideways and the robot crashes blindly into whatever it stopped looking at.

Phase 6: Challenges

Tune it, escape it, override it.

Challenge 1: Fine-Tuning 🛠️

Run your robot. You will notice it behaves strangely!

  1. Open the Serial Monitor (Tools → Serial Monitor, 9600 baud). Watch the live distance readings — are they what you expect when you put your hand in front?
  2. Turning time: Is delay(300) enough to turn ~90°? Try delay(200) or delay(500) until turns are sharp.
  3. Detection distance: Does it crash before stopping? Try raising the threshold from 20 to 30 cm.

Engineering is iteration — observe, adjust, observe again.

Challenge 3: Smart Remote Override 🎮

Goal: combine Session 2’s IR remote with Session 4’s distance check.

You drive the robot with your remote — but if you try to drive it into a wall, the robot refuses the FORWARD command and stops itself.

The Logic inside loop():

  1. Read the forward distance.
  2. Read the IR remote (IrReceiver.decode()).
  3. If distance < 15 AND the command is FORWARD → call car_Stop() and ignore it.
  4. Otherwise → run the command normally (turning and reversing stay allowed — still safe).

Challenge 3: The Scaffold 🛠️

void loop() {
  int distance = measureDistance();

  if (IrReceiver.decode()) {
    uint16_t cmd = IrReceiver.decodedIRData.command;

    if (cmd == 0x46 && distance < 15) {  // 0x46 = FORWARD + wall ahead
      car_Stop();                        // Override: refuse the command
      Serial.println("Wall! Forward blocked.");
    } else {
      handleCommand(cmd);                // From Session 2 Part 5
    }

    IrReceiver.resume();
  }
}

Tip

Reuse handleCommand() from Session 2 Part 5. Replace 0x46 with whatever code your remote’s UP button actually sends.
